Philosophy

core design intent

This is a Wolfenstein-style 2.5D game being evolved into a Quake-style fully 3D game, while preserving and deepening a PS1 aesthetic. The key constraint — and the key design decision — is that all geometry is authored in integer coordinates (ℤ³). This isn't a workaround; it's the point.

design principle
The PS1's GTE had no floating point. Vertex snapping, affine texture warping, and integer coordinate quantization were hardware realities. IVM makes those realities first-class citizens of the authoring format, not just runtime effects.

The smallest representable unit is approximately 10cm in world space, giving clean integer arithmetic for human-scale architecture (a 2m doorway = 20 units, a 1.8m character = 18 units).

aesthetic target
Weirdcore / liminal space. LSD Dream Emulator. Doko Demo Issyo. The old juggling raytracer. Certain Garry's Mod art maps. The Amazing Digital Circus. Petscop. An ARG that doesn't explain itself.

Context

where we came from

The previous map format (.amap) was a 2D tile grid — each cell described a column of space with a wall type, floor texture, ceiling texture, prop, and special trigger. 8 bytes per tile, Wolfenstein-style.

old model
Space was implicit. A tile IS a wall or IS a floor. Geometry was synthesized from the grid at runtime. Walls could only be axis-aligned, height was uniform, no slopes, no overhangs.
new model
Space is explicit. Vertices, edges, faces stored directly. The renderer draws what is there. No grid, no implied geometry. Full 3D. Camera pitch unlocked.

The rendering pipeline is already 3D — rasterized triangles via wgpu, with an authentic vertex snap shader, affine texture warping blend, and FIR NTSC encode/decode passes. The camera was simply locked to no pitch. The transition is primarily a format and mesh-generation change, not a renderer change.

Geometry Model

format / geometry

IVM geometry is a standard indexed mesh, but with the constraint that all vertex positions are integers. Not a voxel grid, not axis-aligned only — a fully general mesh where coordinates happen to be in ℤ³.

// Formal description
Vertices  = points in ℤ³
Edges     = connect two vertices (by index)
Faces     = ordered list of vertex indices (winding defines normal direction)
Normals   = auto-generated from face winding (cross product, normalized at build time)
UVs       = projected at load time (dominant-axis planar projection)
           // explicit per-face-vertex UVs can be added later

1 IVM unit ≈ 10cm in world space. This gives clean integers for common measurements and is dense enough for fine architectural detail without needing sub-unit precision.

Normals

Computed automatically from face winding at mesh build time. Never stored in the authored format. The cross product stays integer until normalization:

fn face_normal(v0: [i32; 3], v1: [i32; 3], v2: [i32; 3]) -> [f32; 3] {
    let e0 = [v1[0]-v0[0], v1[1]-v0[1], v1[2]-v0[2]];
    let e1 = [v2[0]-v0[0], v2[1]-v0[1], v2[2]-v0[2]];
    // cross product stays integer
    let n = [
        (e0[1]*e1[2] - e0[2]*e1[1]) as f32,
        (e0[2]*e1[0] - e0[0]*e1[2]) as f32,
        (e0[0]*e1[1] - e0[1]*e1[0]) as f32,
    ];
    let len = (n[0]*n[0] + n[1]*n[1] + n[2]*n[2]).sqrt();
    [n[0]/len, n[1]/len, n[2]/len]
}

Map Objects

format / objects

Geometry is grouped into map objects — named collections of vertices and faces. Each object has a unique ID. Objects are the authoring unit; at runtime they can be preserved or flattened.

Merge Behaviour

When an edge is drawn between a vertex in object A and a vertex in object B, the newer object is absorbed into the older one. All of the newer object's vertices are reindexed into the older object's vertex list. The older object's ID and properties are preserved.

union-find
This is essentially a union-find / disjoint set structure applied to geometry. Each object is a connected component. Connecting two components merges them, with the older ID as canonical.

Runtime vs Edit Time

edit time

Object boundaries are meaningful. Merge-on-connect is active. Object focus mode isolates one object. Per-object colours in view modes.

runtime

Objects are preserved in memory to support seamless edit/game switching. MapMesh is a derived flat cache rebuilt when geometry changes.

Cylinder Primitive

A procedural primitive defined by two vertex indices (axis endpoints), an integer radius, and a side count. Generated ring vertices are computed at load time in fixed-point space. The integer source data stays clean.

struct CylinderPrimitive {
    v_start: u16,    // index into object vertex list
    v_end:   u16,
    radius:  i32,    // integer units
    sides:   u8,     // typically 8 or 12
}

Note: this primitive doubles as the visual pipe representation of edges in the editor (see Editor section).

Texture Storage

format / textures

Textures are embedded directly in the .ivm file. No external references, no companion files. The format is fully self-contained.

Encoding: QOI

QOI (Quite OK Image) is the right choice for this use case. It is designed for pixel art and low-color content — exactly what PS1-style textures are. Fast decode (no zlib, just a state machine), decent compression, trivially simple spec.

max texture size

128 × 128

65KB raw RGBA. ~10–20KB QOI compressed. Twenty textures ≈ 300KB total.

qoi encode/decode
// encode
let enc = qoi::encode_to_vec(
    &rgba, w, h)?;
// decode
let (hdr, px) = qoi::decode_to_vec(
    &bytes)?;

Texture Section Layout

--- per texture ---
u8          name_len
[u8; N]     name        // length-prefixed, no null terminator
u32         data_len
[u8; N]     qoi_data    // RGBA QOI encoded pixels

Face texture_id fields are indices into this table. The string table entry for each texture ID gives the human-readable name for editor display.

Entities

format / entities

Entities are non-geometry objects: spawn points, lights, triggers, enemies, props. They use a Quake-style key/value property system — flexible enough to describe anything without a rigid per-type schema.

struct Entity {
    id:         u32,
    position:   [i32; 3],       // ℤ³ position
    kind:       EntityKind,     // Spawn, Light, Trigger, Enemy, Prop, ...
    properties: HashMap<String, String>,  // quake-style kvs
}
quake kv system
Key/value strings are flexible enough to describe any entity type without changing the format. New entity types can be added without a format version bump. Serialized in the binary as length-prefixed string pairs.

What was previously encoded in the tile grid as special_type, special_data, prop_type, and prop_variant bytes all becomes entity KV pairs. Position replaces tile coordinates.

Editor Design Language

editor / aesthetic

The editor does not look like Blender. There is no floating UI, no gizmo overlays, no toolbar. The editing tools manifest as physical objects in the same PS1-rendered world. The editor is the game world.

aesthetic reference
Petscop. An ARG. Something that doesn't explain itself. The Windows XP pipe screensaver rendered through an NTSC filter. A tool that seems to have existed before you found it.

Vertex Spheres

Each vertex is a low-poly sphere (octahedron or icosphere subdivision 1 — 8 faces, very PS1). Physical geometry, goes through the full render pipeline including vertex snap and NTSC filter.

unselected

VIC-20 light red #b66862 — dusty, not aggressive. Static. Radius ~0.12 world units.

selected

Pulsates between VIC-20 light yellow #ffffb0 and white #ffffff via sine wave on anim_elapsed_ms. Vertex color updated on CPU each frame — no shader change.

// VIC-20 #ffffb0 → #ffffff pulse
fn selection_pulse_color(anim_elapsed_ms: f64) -> [u8; 4] {
    let t = ((anim_elapsed_ms * 0.003).sin() * 0.5 + 0.5) as f32;
    // #ffffb0 = [255, 255, 176] — lerp to white [255, 255, 255]
    [255, 255, (176.0 + t * 79.0) as u8, 255]
}

Edge Pipes

Edges are rendered as cylinder primitives — the same cylinder primitive used for map geometry. Thin: radius ~0.05–0.08 world units (5–8cm), visually distinct from world geometry. Sphere joints at each vertex where edges meet, slightly larger than pipe radius (~0.12 units).

The pipe visuals wobble with camera movement due to vertex snap. This looks exactly right for the aesthetic.

Object Colours

Each map object has a persistent colour assigned from the VIC-20 palette based on its ID. The VIC-20 colours are almost-right in a deeply uncanny way — recognisable as real colours but slightly wrong in hue and value in a way modern palettes never are. Nothing is fully saturated, nothing is neutral; every colour is contaminated by another hue.

fn object_color(id: u32) -> [u8; 4] {
    const PALETTE: [[u8; 4]; 8] = [
        [0xe9, 0x9d, 0xf5, 255],  // #e99df5 — wrong lilac

        [0xc5, 0xff, 0xff, 255],  // #c5ffff — blown-out cyan

        [0x7e, 0x70, 0xca, 255],  // #7e70ca — washed purple
        [0xff, 0xff, 0xb0, 255],  // #ffffb0 — pale wrong yellow
        [0x85, 0xd4, 0xdc, 255],  // #85d4dc — muted teal
        [0xa8, 0x73, 0x4a, 255],  // #a8734a — dark brown, earthy
    ];
    PALETTE[(id as usize) % PALETTE.len()]
}

Interaction Model

editor / interaction

Stolen from the best parts of three tools and combined:

from blender

Axis locking: shift+x/y/z constrains movement to that axis. Scroll to move along it. Clean and fast.

from fusion 360

Plane editing mode. A translucent plane appears on the selected axis touching the current working point. All clicks land on this plane.

from illustrator / figma pen tool

Click-and-place workflow. Clicking places a new vertex. Pen mode auto-chains. Separate edge tool for explicit A→B connections.

Plane Mode

Enter with alt+x, alt+y, or alt+z. A translucent plane appears on the chosen axis, touching the current working point. Shift-scroll moves the plane along its perpendicular axis. All clicks while in plane mode produce vertices on that plane — if working on an X plane, you are locked to that X coordinate and move freely in Y and Z.

snapping is implicit
Since all coordinates are integers, every click in plane mode just rounds the plane intersection to the nearest integer. There is no snap toggle. It is always on. This is a consequence of ℤ³.

The Plane Ghost

Not geometry — a fullscreen shader pass, like the sky pass. A ray is cast from the camera through each fragment and intersected with the plane equation. The plane extends to infinity, fading with distance via exponential fog. Grid lines fall at integer boundaries — the same boundaries where vertex snap quantizes — so the grid is literally showing you where vertices can exist.

The plane colour is determined by its axis, sourced from the VIC-20 palette. Switching axis with alt+x/y/z snaps the whole plane to the new colour.

axisfillgrid linesvic-20 source
X #b66862 #e9b287 lt-red / peach
Y #bdcc71 #ffffb0 yellow-green / lt-yellow
Z #42348b #7e70ca dk-blue / lt-blue
ground #559e4a #92df87 dk-green / lt-green — always visible

The ground grid at y=0 is always active in edit mode regardless of plane lock state. It is fainter than the active plane, giving a permanent spatial anchor — the endless grid floor is a staple of the liminal aesthetic. When the active plane is Y at y=0, the two overlap; they blend additively so the intersection reads brighter, like two signals interfering.

// plane pass uniforms
struct PlaneUniforms {
    inv_view_proj: mat4x4<f32>,
    camera_pos:    vec4<f32>,
    plane_color:   vec4<f32>,   // rgb from VIC-20 axis colour
    plane_value:   f32,          // world coordinate of the plane
    plane_axis:    u32,          // 0=X  1=Y  2=Z
    fill_alpha:    f32,          // ~0.06
    line_alpha:    f32,          // ~0.70
}

// fragment — ray/plane intersection + integer grid
let t  = (uniforms.plane_value - ray_origin[axis]) / ray_dir[axis];
let hit = ray_origin + ray_dir * t;
let grid  = grid_lines(hit, plane_axis);   // fwidth AA at integer boundaries
let alpha = mix(uniforms.fill_alpha, uniforms.line_alpha, grid)
           * exp(-t * fog_density);        // distance fade to infinity
return vec4(uniforms.plane_color.rgb, alpha);

Selection

Vertices are red (unselected) or yellow-white pulsing (selected). Multi-select via shift-click. Lasso tool: since all vertices project to screen space for rendering, lasso is a 2D point-in-polygon test against projected positions — very cheap. Lasso outline drawn into the overlay pixel buffer.

Object Focus Mode

Press to enter focus on a single object. All raycasts and selections are filtered to that object only. All plane lock and axis lock controls still function. Escape exits. The TextLayer displays the focused object ID and name.

View Modes

editor / view modes

Four view modes, switchable at any time. All go through the same wgpu pipeline — the only difference is what values are put into SceneVertex.color and whether face geometry is included in the vertex buffer.

wireframe
Only pipe cylinders and vertex spheres. No face geometry emitted. Map faces omitted from draw call entirely.
object colours
Faces rendered flat using object_color(id) baked into vertex colors. A 1×1 white atlas pixel drives everything through vertex color. No UV lookup needed.
textured
Faces with atlas UVs. Vertex color neutral white [255,255,255,255]. Same as gameplay render mode.
shaded
UVs plus vertex color carrying baked shadow/light data. The final look. Phong shading may be added later as an optional pass.
enum ViewMode {
    Wireframe,
    ObjectColors,
    Textured,
    Shaded,
}
// build_editor_mesh branches on ViewMode when emitting SceneVertex data
// rebuild on mode change — at PS1-scale geometry this is instant
ntsc on everything
All four view modes go through the NTSC encode/decode passes. The oversaturated flat colours of object-colour mode bleeding chroma into each other through the filter is the LSD Dream Emulator look.

Editor State Machine

editor / states
IDLE
  • shift+click vertex → vertex added to selection
  • click empty space → lasso start OR deselect all
  • click empty + pen mode → place new vertex on current plane
  • alt+x/y/z → enter PLANE_MODE (axis set)
  • click object → VERTEX_SELECTED
PLANE_MODE (axis locked)
  • click → new vertex at plane intersection, rounded to ℤ³
  • shift+scroll → translate plane along its normal
  • click existing vertex → select / start edge
  • alt+x/y/z → change plane axis
  • escape → exit to IDLE
VERTEX_SELECTED
  • shift+x/y/z + scroll → translate along axis
  • delete → remove vertex, update faces
  • click another vertex → draw edge; merge objects if cross-boundary
  • shadow tool → open vertex color painter
  • escape → deselect, return to IDLE
OBJECT_FOCUS (wraps above)
  • all above states active → raycasts only hit focused object
  • plane lock / axis lock → function normally
  • escape → exit focus, return to IDLE

Vertex Format

renderer / vertex

Adding a color field to SceneVertex for vertex shading. rust

#[repr(C)]
#[derive(Clone, Copy, Pod, Zeroable)]
pub struct SceneVertex {
    pub(crate) position: [f32; 3],   // 12 bytes
    pub(crate) uv:       [f32; 2],   //  8 bytes
    pub(crate) color:    [u8;  4],   //  4 bytes — Unorm8x4
}                                     // 24 bytes total, naturally aligned

impl SceneVertex {
    pub const ATTRIBUTES: [wgpu::VertexAttribute; 3] =
        wgpu::vertex_attr_array![
            0 => Float32x3,
            1 => Float32x2,
            2 => Unorm8x4,   // auto-normalized to [0,1] in shader
        ];
}

Unorm8x4 means wgpu normalizes the bytes to vec4<f32> in [0.0, 1.0] automatically. Default white [255, 255, 255, 255] = no visible change to existing geometry. 24 bytes total, naturally aligned, bytemuck::Pod is satisfied.

gouraud shading for free
Vertex color is interpolated linearly across each triangle by the rasterizer. This is Gouraud shading — exactly how the PS1 did it. Affine interpolation of vertex colors (no perspective correction) is what you get here for free, since it is just a plain vec4 interpolant. Authentically PS1 without extra work.

Shader Changes

renderer / wgsl

Minimal changes to the existing vertex/fragment shader. wgsl

// vertex input — add color
struct VertexIn {
    @location(0) position: vec3<f32>,
    @location(1) uv:       vec2<f32>,
    @location(2) color:    vec4<f32>,  // Unorm8x4 arrives normalized
};

// vertex output — pass through
struct VertexOut {
    @builtin(position) position: vec4<f32>,
    @location(0) uv:          vec2<f32>,
    @location(1) affine_uv:   vec3<f32>,
    @location(2) color:       vec4<f32>,  // added
};

// vs_main — add one line
out.color = input.color;

// fs_main — multiply texture by vertex color
let color = textureSample(t_atlas, s_atlas, uv) * input.color;
if (color.a < 0.05) { discard; }
return color;

The affine warp trick (affine_uv carrying uv * w and w, mixed in fragment shader) is completely unaffected. Vertex color is interpolated separately and applied as a final multiply.

Edit / Game Switch

runtime / modes

The editor is part of the game binary, not a separate tool. Switching between edit and gameplay mode is seamless — both modes render through the same pipeline with the same camera and world state.

enum AppMode {
    Game,
    Editor(EditorState),
}

// In App::render():
match self.mode {
    AppMode::Game => {
        // existing path: assemble scene from game state
        // render_frame(..., editor: None)
    }
    AppMode::Editor(ref ed) => {
        // assemble scene from EditorState
        // render_frame(..., editor: Some(ed))
    }
}
renderer is mode-agnostic
The renderer does not know which mode the app is in. It draws what it is given. The Map object graph is always in memory — it cannot be thrown away since edit mode may be entered at any time. MapMesh is rebuilt when geometry changes; the renderer always uses the current MapMesh.

When entering edit mode, the game pauses, mouse capture mode switches from ConfinedWarp/Locked to free cursor, and the TextLayer switches to editor chrome. The 3D camera and world position are preserved — you are looking at the same place you were playing from.
